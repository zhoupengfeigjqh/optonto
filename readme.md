总目标：构建一个本体开发平台，采用前后端分离形式，具体包含如下功能

1 前端功能

1.1 技术选型：typescript、react、next.js、nodejs、nginx、echarts

1.2 页面色调：黑色科技背景

1.3 代码位置：./frontend/

1.4 主页端口为81，页面正上方显示 OPTONTO本体市场，整体布局为左侧菜单栏和右侧功能区

1）页面左侧任务栏显示场景名称，便于用户按场景快速切换

2）任务栏上方有新建场景，点击后弹出对话框，输入场景名称-场景描述

3）点击任务栏中的场景后，页面中间显示**服务卡片列表**，即这个场景下创建的本体图标，卡片中包含：本体名称、本体介绍、以及这个本体的class数量、relation数量、property数量、action数量和rule数量。

4）可以点击卡片列表跳转到本体设计页面，通过nginx路由过去

5）可以通过点击新建本体按钮，弹出本体创建对话框，输入本体名称、本体描述和本体创建人，确认后也跳转到本体设计页面

6）可以删除本体和删除场景，注意若删除场景，必须要求该场景下的本体为空；删除时必须要用户二次确认并输入本体或场景名字验证，避免误删！

1.5 本体设计页面端口为8010，页面左上方显示场景名和本体名，整体布局为左侧任务栏和右侧功能区

1）页面左侧任务栏，依次为本体设计和本体视图

2）本体设计：点击后，任务栏上展开4个子项，依次为概念、关系、行为、规则、事件、业务流程和文件浏览

（1）概念：以表格栏展示，包括概念名和概念描述；点击新增概念，增加一行，也可删除概念；点击每个概念的管理属性按钮，右侧弹出对话框设置属性，可以新增属性，输入属性名和属性类型，也可以删除属性；

（2）关系：以表格栏展示，包括关系名、源概念（下拉选择已创建的概念）、目标概念（下拉选择已创建的概念）、基数（下拉选择1:N，N:1或N:M）和关系说明；可点击新增关系，也可以删除关系。

（3）行为：以表格形式展示，包括行为名称、行为类型（下拉框，选择CREATE/READ/UPDATE/DELETE）、行为描述、接口协议（HTTP/SQL）、接口地址（点击弹出编辑：HTTP下显示URL输入，SQL下显示SQL代码编辑器且语法高亮）、请求方式（下拉选择，HTTP协议下，显示POST/GET，SQL下设为灰且内容为空）、接口参数（点击弹窗JSON配置）、关联概念（下拉选择，可选择多个概念）、接口测试（点击后，弹出对话框显示接口测试结果，否则弹出报错结果）。

（4）规则：以表格形式展示，包括名称、规则描述、关联行为（下拉选择，可以选多个行为，不选则默认没有）

（5）事件：以表格形式展示，包括关联行为（下拉选择，只能选一个行为，不选则默认没有）、事件名、事件描述后续触发（下拉选择，可选多个行为，不选则默认没有）

（6）业务场景：以表格形式展示，包括流程名、流程描述和关联概念（下拉框选择，不选择默认全部）

（7）文件浏览：（1）~（5）所创建的内容保存为yaml，并以yaml形式展示在页面端；对该文件修改后，同步到前后端；

1.6 本体视图

1）采用echarts绘制本体视图，采用力导向图方式构建

2）本体设计页面左侧任务栏点击本体视图后，自动读取yaml，并将结果展示在页面中。

3）本体视图包括概念、关系、行为和规则，一共4类节点，节点只显示名称。节点和连线按类型区分样式：

   - **概念节点**：尺寸较大，与其他类型节点颜色不同，突出显示
   - **行为节点**：尺寸较小，颜色与概念节点区分
   - **规则节点**：尺寸较小，颜色与概念和行为节点区分
   - **关系连线**：显示在概念节点之间的连线上，关系名标注在连线旁。不同类型的关系可用虚实线或不同颜色加以区分

4）一阶关系指直接连接当前节点的关系。点击概念后，右侧弹窗显示该概念的属性及一阶关系信息，同时在echart中高亮其一阶关系节点和连线。

5）可以选择业务流程，在echarts中高亮所选业务流程中的概念和关系

1.7 本体测试

1）功能区中有两块，中间为大语言模型对话窗口，采用和豆包一样的对话方式下的方式，SSE流式输出

2）右侧为一个跟踪窗口，大语言模型在推理过程中，该弹窗里实时输出如果调用了的工具，以及该工具关联的接口、概念和规则等简介信息。

3）新建对话时，这两块窗口均为空，对话结束后，这两块窗口内容不变。

4）对话历史记录可以查看和删除，删除时需要二次确认。


2 后端内容

2.1 技术栈：Python3.12，FastAPI，SQLITE，大语言模型Agent采用langchain==1.2.10和langgraph==1.0.8开发，其余用最新版本库开发，注意版本适配问题。

2.2 代码保存在./core-backend/ 

2.3 大语言模型相关：

1）模型名称在 `./config/config.yaml` 的 `models.model` 配置（agent-backend 启动时读取，无效时回退 deepseek-v4-flash）；API Key 等密钥放在 `./config/.env`（如 `DEEPSEEK_API_KEY`）。两者职责分离，`config/` 目录不入库，可参考 `config/config.yaml.example` 新建

2）大语言模型**不使用推理模式**（即不开启思维链/Reasoning），采用标准对话模式进行响应

3）需要持久化存储对话数据，对话结束后，将对话数据保存到json文件中

4）大语言模型对话时，需要把本体文件yaml加载到系统提示词中

5）行为触发相关工具调用，调用前会自动根据行为接口解析和拼接参数，具体工具有：
   1）POST工具
   2）GET工具
   3）SQL工具
   PS：注意，调用报错需要返回错误信息！

6）大语言模型调工具前，需要有个中间件middleware，用于本体预定义的规则校验。这个校验采用大语言模型，根据规则对上文内容进行校验，校验通过后才允许调用工具。否则，返回校验不通过的信息，并终止对话。

2.4 数据保存：

1）本体设计的数据存储在yaml文件中，保存的文件夹为./.data/onto_market/场景名/本体名/xxx.yaml

2）通过行为接口的读写数据存入到数据库中（行为为 SQL 类型时查 MySQL）

3）大语言模型等相关配置文件保存在 ./config/xxx.yaml

4）.env保存环境变量，数据放在./config/.env文件中

5）大语言模型的对话数据保存在./.data/onto_market/场景名/本体名/threads/xxx.json，按thread_id区分，每个thread_id为一个{thread_id}.json文件

3 项目目录结构

```
optonoto/
├── frontend/                  # 前端（React/Next.js/TypeScript）
│   ├── nginx/                 # Nginx 路由配置
│   └── ...                    # 页面组件、路由、状态管理
├── core-backend/              # 本体核心 API（FastAPI/Python + MCP Server）
├── business-backend/          # 业务数据源 API（Java/Spring Boot）
├── agent-backend/             # 多 Agent 编排服务（Node/pi-agent-core）
├── .data/                     # 运行时数据（挂载进容器）
│   └── onto_market/           # 本体数据存储
│       └── {场景名}/
│           └── {本体名}/
│               ├── xxx.yaml   # 本体设计定义（概念/关系/行为/规则/事件）
│               └── threads/   # 对话历史 JSON 文件
├── config/                    # 配置文件
│   ├── xxx.yaml               # 大语言模型等配置
│   └── .env                   # 环境变量
└── readme.md                  # 本文件
```
