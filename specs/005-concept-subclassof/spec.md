# 功能规范：概念继承（subClassOf）与继承属性收窄

**特性分支**: `005-concept-subclassof`

**创建日期**: 2026-10-19

**状态**: 已实现（2026-10-19；验收记录见 [tasks.md](./tasks.md)）

**输入**: 用户 2026-10-19 决策回合（字段名 `sub_class_of`、多级传递、同名继承优先 + 三个维度可收窄、父删除清子引用）

## 用户场景与测试 *（必填）*

### 用户故事 1 - 概念可声明父概念并自动继承属性（优先级：P1）

作为本体设计者，我希望在概念上选择最多一个父概念（OWL `subClassOf`），保存后子概念自动拥有父概念声明的全部属性，
这样"采购单是一种单据"这类语义不必靠复制属性来表达，父概念改属性子概念自动跟随。

**优先级理由**：这是继承体系的地基；不落地则后续收窄、级联、运行面读取都无从谈起。

**独立验证**：给子概念选择父概念并保存，点击「属性」能看到继承行（灰色、只读），属性数显示"自有 + 继承"。

**验收场景**：

1. **Given** 概念 `单据` 有 `status`/`amount` 属性，**When** `采购单` 选择父概念 `单据` 并保存，**Then** `采购单` 的有效属性 = 自有 + `status` + `amount`，且继承行标「继承自 单据」。
2. **Given** 父概念已有属性 `status`，**When** 子概念新增同名属性，**Then** 保存前弹出确认、保存后按父定义继承（子概念不落同名自有声明）。
3. **Given** 概念 A→B→C（三级链），**When** 查看 C 的属性，**Then** 同时包含 A、B 声明的属性。
4. **Given** 父概念选择器，**When** 编辑概念 A，**Then** 候选列表排除 A 自身及其全部后代（前端先防环）。

---

### 用户故事 2 - 继承属性只能收窄，不能放宽（优先级：P1）

作为本体设计者，我希望继承来的属性在子概念里只读，仅允许收窄枚举（只能删）、取值范围（不能超过父）、匹配模式（可任意调整），
这样继承体系不会被子概念悄悄放大成不一致的约束。

**优先级理由**：与故事 1 同批交付，否则"只读"无法落地。

**独立验证**：继承行的枚举下拉只能勾选父枚举内的值；范围输入被父上下界钳制；模式可任意编辑；其余单元格禁用。

**验收场景**：

1. **Given** 父 `status.enum=[草稿,审批中,已通过]`，**When** 子只勾选 `[草稿,审批中]`，**Then** 子有效枚举为两者交集；父后续删掉 `审批中` 后子自动只剩 `草稿`。
2. **Given** 父 `amount` 范围 `[0,100000]`，**When** 子填 `max=200000`，**Then** 前后端均拒绝（400）。
3. **Given** 父 `memo.pattern=^[A-Z]{2}$`，**When** 子改为 `. +` 或清空，**Then** 保存成功（模式可任意调整，空串 = 清除）。
4. **Given** 子对继承属性点「恢复继承」，**Then** 该属性的收窄被移除，完全回到父定义。

---

### 用户故事 3 - 父概念变更时保持数据自洽（优先级：P2）

作为本体设计者，我希望删除父概念能清空子概念引用而不删子概念，父概念改名能级联改写引用，
这样继承关系不会悬空，也不会因为一次删除丢失整棵子树。

**独立验证**：删除父概念后子概念仍在、`sub_class_of` 为空；父改名后子概念指向新名。

**验收场景**：

1. **Given** `采购单.sub_class_of=单据`，**When** 删除 `单据`，**Then** `采购单` 保留、父引用与收窄清空。
2. **Given** 同上，**When** 把 `单据` 改名为 `业务单据`，**Then** `采购单.sub_class_of=业务单据`。
3. **Given** 父概念删除了某属性，**When** 再次保存子概念，**Then** 该属性的孤儿收窄被自动剪除。

---

### 用户故事 4 - 三端读取口径一致（优先级：P2）

作为平台维护者，我希望设计面（core API）、运行面（agent / MCP）看到的概念属性都是有效属性，
这样继承属性不会在规划期参数校验、约束回溯、实例图里凭空消失。

**独立验证**：`GET /concepts` 的 `inherited_attributes`、`mcp-shared` 加载后的概念 `attributes`、
agent 网关 `getBehaviorMeta().concepts[].attributes` 三者内容一致（收窄已合成）。

**验收场景**：

1. **Given** 子概念继承父 `status`，**When** 为其行为配置状态跃迁，**Then** 状态下拉来自继承后的枚举（含收窄）。
2. **Given** 继承属性，**When** 建立关系端点，**Then** 保存成功（不再报"关联属性不存在"）。
3. **Given** 环 / 悬空父概念的历史脏数据，**When** 运行面读取，**Then** 截断并告警，不抛错、不挂整次对话。

## 需求 *（必填）*

- **FR-001**：`ConceptItem` 新增 `sub_class_of: string | null`（至多 1 个父概念；空 = 根概念），读时兼容 `subClassOf`。
- **FR-002**：`ConceptItem` 新增 `attribute_restrictions: {属性名: {enum?, min?, max?, pattern?}}`；空维度不落盘。
- **FR-003**：有效属性 = 自有（未被继承同名占用）+ 父概念有效属性，多级传递；同名**继承优先**。
- **FR-004**：收窄合成：enum 取交集（只删不增）、min 取最大 / max 取最小、pattern 覆盖（空串 = 清除）。
- **FR-005**：写入校验：父概念必须存在、不得自引用/成环；收窄只能作用于继承属性且不得放宽；非法正则 400。
- **FR-006**：级联：父删除 → 清空子 `sub_class_of` 与 `attribute_restrictions`（子概念保留）；父改名 → 级联改写引用；同名自有声明保存时自动剔除。
- **FR-007**：读取视图：`GET /api/ontologies/{id}/concepts` 返回 `inherited_attributes`（带 `inherited_from` / `restricted`），`attributes` 仍只含自有。
- **FR-008**：运行面（mcp-shared 加载出口、agent 网关）概念 `attributes` 一律为有效属性。
- **FR-009**：读侧对环/悬空父概念截断 + warning，不抛错；写侧 400。
- **FR-010**：设计面所有属性消费点（关系端点、行为 status 枚举、规则生成上下文、本体摘要、实例图、本体图）改用有效属性。

## 关键实体

- **概念（Concept）**：`name / display_name / description / terms / instance_label / sub_class_of / attributes / attribute_restrictions`。
- **继承属性视图（InheritedAttribute）**：属性字段 + `inherited_from`（实际声明概念）+ `restricted`（是否被本概念收窄）。

## 边界与不做

- 不做多父概念（`subClassOf` 在本平台收敛为单值）。
- 不做"放宽"型覆盖：子概念不能新增父枚举值、不能扩大父范围、type/unique/required/展示字段一律不可改。
- 不把继承属性物理复制进 YAML（避免副本过期与双写）。
- 不改数据库（平台为文件存储，无迁移）。

## 成功标准

- 单级/多级继承、收窄合成、级联、三端读取口径均有自动化用例覆盖。
- 存量 YAML（无新字段）零改动可加载，行为与现状一致。
