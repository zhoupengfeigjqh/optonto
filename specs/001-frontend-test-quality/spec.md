# 功能规范：前端测试体系与覆盖率门禁，并拆分超长组件

**特性分支**: `001-frontend-test-quality`

**创建日期**: 2026-09-28

**状态**: 草稿

**输入**: 用户描述："建立前端测试体系与覆盖率门禁，并拆分超长组件"

## 用户场景与测试 *（必填）*

### 用户故事 1 - 建立前端测试基础设施与覆盖率门禁（优先级：P1）

作为前端开发者，我希望用**一条命令**运行全部前端单元测试并看到覆盖率报告，且覆盖率低于阈值时命令失败，
这样"组件必须有单测、核心逻辑覆盖率 ≥80%"就不再是纸面要求，而是可执行的门禁。

**优先级理由**：当前前端**零测试、无测试运行器、无覆盖率配置**，是章程 III 最严重的合规缺口；
没有基础设施，后续所有组件测试都无法落地，故必须先建。

**独立验证**：在仓库根执行 `cd frontend && npm run test:coverage`，可看到 vitest 输出用例结果与覆盖率表；
人为把某模块的测试删掉使覆盖率低于阈值时，命令以非零码退出。

**验收场景**：

1. **Given** 尚未安装测试依赖的仓库，**When** 执行 `npm install && npm run test:coverage`，**Then** 命令成功拉取依赖、运行用例并输出覆盖率报告。
2. **Given** 覆盖率已达标，**When** 执行 `npm run test:coverage`，**Then** 命令以退出码 0 结束并打印各项覆盖率百分比。
3. **Given** 覆盖率低于阈值（如语句覆盖率 < 80%），**When** 执行同命令，**Then** 命令以非零退出码结束并明确指出未达标的指标。

---

### 用户故事 2 - 核心组件具备单元测试（优先级：P2）

作为前端开发者，我希望每个组件都有对应测试，且用例覆盖**属性传递、事件触发、边界条件**三类条件，
这样组件重构或他人修改时能被测试兜住。

**优先级理由**：章程 III 的硬性要求（每组件必须有单测、三类条件必须覆盖）。基础设施就绪后按优先级补测。

**独立验证**：改动某组件的 props 处理逻辑（如把 `display_name || name` 改成只取 `name`），对应测试应当失败。

**验收场景**：

1. **Given** 一个展示型组件，**When** 传入不同 props，**Then** 渲染结果与 props 一致（属性传递覆盖）。
2. **Given** 一个含交互的组件，**When** 触发点击/键盘事件，**Then** 回调被调用且状态按预期变化（事件触发覆盖）。
3. **Given** 空数据、超长文本、缺失可选字段等边界输入，**When** 渲染组件，**Then** 不抛异常且展示兜底内容（边界条件覆盖）。

---

### 用户故事 3 - 超长组件拆分到 500 行以内且行为不变（优先级：P3）

作为前端开发者，我希望把超过 500 行的组件拆成职责单一的多个子组件/Hook，
这样单文件符合章程上限，且可读性与可测试性提升。

**优先级理由**：章程 I 的硬性上限；但拆分属结构调整，风险高于建测试体系，故排在 P3，
且必须在测试护栏（P1/P2）就绪后再做。

**独立验证**：拆分前后 `npx tsc --noEmit` 通过、测试全绿、页面手工路径一致（展开/折叠、参数编辑、流式对话）。

**验收场景**：

1. **Given** `AgentApp.tsx`（1463 行），**When** 拆分为子组件与 Hook，**Then** 每个文件 ≤500 行且 `npm run build` 成功。
2. **Given** 拆分完成，**When** 走查原有交互路径，**Then** 行为与拆分前一致（无功能回归）。

---

### 边界情况

- **第三方库在 jsdom 下不兼容**：Ant Design 依赖 `matchMedia`，图表/表格依赖 `ResizeObserver`，jsdom 默认不提供 —— 测试环境必须提供统一 stub。
- **网络不可用**：测试过程中禁止真实网络请求；`fetch` 必须被 stub 或走 mock。
- **LLM 调用**：涉及大模型的逻辑不得依赖真实模型输出做断言（章程 III）。
- **覆盖率一次性达标困难**：允许按目录配置阈值（核心模块高、展示组件分批补），但**总阈值不得低于章程下限 80%**。
- **拆分导致行为漂移**：拆分必须先建测试再动结构（P1/P2 先于 P3）。

## 需求 *（必填）*

### 功能需求

- **FR-001**: 前端 MUST 引入单元测试运行器与组件测试工具，且技术选型理由 MUST 记录在 plan 中（章程"技术治理与依赖管控"）。
- **FR-002**: `frontend/package.json` MUST 提供 `test` 与 `test:coverage` 两条脚本。
- **FR-003**: 覆盖率统计 MUST 覆盖语句、分支、函数、行四个维度，且阈值 MUST 不低于 80%。
- **FR-004**: 每个组件 MUST 有对应测试文件，用例 MUST 覆盖属性传递、事件触发、边界条件三类条件。
- **FR-005**: 测试 MUST 可在无网络环境下运行；外部 HTTP 调用 MUST 被 stub。
- **FR-006**: 测试环境 MUST 提供 jsdom 缺失 API 的统一 stub（`matchMedia`、`ResizeObserver` 等）。
- **FR-007**: 前端所有 `.tsx` 文件 MUST ≤500 行（后续新增同受约束）。
- **FR-008**: 组件拆分 MUST NOT 改变对外行为（props 契约、事件、渲染结果）。
- **FR-009**: 前端合并门禁 MUST 为「`tsc --noEmit` + `test:coverage`」双双通过。
- **FR-010**: 测试 MUST NOT 依赖真实 LLM 或真实后端服务。

### 关键实体

- **测试基础设施配置**：运行器配置、覆盖率阈值、jsdom 环境 stub、setup 文件。
- **组件测试**：与被测组件一一对应，断言 props → 渲染、事件 → 回调、边界 → 兜底。
- **拆分后的组件树**：`AgentApp` 拆分出的子组件与自定义 Hook，各自职责单一。

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 执行 `npm run test:coverage` 单条命令即可完成「安装依赖 → 运行测试 → 输出覆盖率 → 门禁判定」。
- **SC-002**: 覆盖率四维指标均 ≥80%，且低阈值时命令返回非零退出码（门禁真实生效）。
- **SC-003**: 前端所有 `.tsx` 文件行数 ≤500（拆分前超限 6 个，拆分后为 0 个）。
- **SC-004**: 被测组件的用例覆盖属性传递、事件触发、边界条件三类条件（逐组件核对）。
- **SC-005**: 全量前端测试执行时间 <60 秒（本地）。

## 假设

- 前端技术栈为 Next.js 14（App Router）+ React 18 + TypeScript + Ant Design 5 + Tailwind。
- 引入测试相关 devDependencies 属章程 III 的强制要求，符合"禁止非必要依赖"的例外，但必须在 plan 中说明选型理由。
- 测试运行于 jsdom 环境（非真实浏览器），不覆盖像素级视觉回归。
- 超长文件的拆分以「结构等价、行为不变」为验收基线，不追求顺带重构业务逻辑。
- 边缘展示型组件允许分批补测，但总覆盖率不得低于 80%。
