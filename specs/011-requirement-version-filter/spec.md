# 功能规范：需求汇总按版本号筛选

**Feature Branch**: `011-requirement-version-filter`（仓库未启用 `before_specify` hook，未自动创建分支）

**Created**: 2026-11-20

**Status**: Draft

**Input**: User description:

> 新增一个需求。在需求汇总这里，右上角有个下拉选择（全部和所有版本号），可以按照版本号进行筛选，即选择版本号后则只显示这个版本号的需求汇总信息。

## 背景

「需求汇总」页面当前把当前场景/本体下**所有**已导出的需求文档平铺在表格里，只能靠肉眼在「版本」列里找。
随着版本迭代，同一个本体下会积累 v1.0、v1.1、v2.0 等多批文档，混在一起时既难核对"某一版到底导出了哪些文档"，也容易误删别的版本。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按版本号过滤需求文档 (Priority: P1)

本体设计者进入需求汇总后，希望能直接选定某个版本号，只看到该版本导出的需求文档，而不是在整张表里逐行找版本列。

**Why this priority**: 这是本需求的全部价值所在；没有它，其余边界处理都没有承载对象。

**Independent Test**: 页面右上角出现版本号下拉（默认「全部」）；选 v1.0 后表格只剩 v1.0 的行，选「全部」后恢复全部行。

**Acceptance Scenarios**:

1. **Given** 当前本体下有 v1.0、v1.1、v2.0 三个版本的需求文档，**When** 进入需求汇总，**Then** 下拉默认显示「全部」，表格显示全部文档。
2. **Given** 下拉已展开，**When** 选择 v1.1，**Then** 表格只显示 v1.1 的文档，其余版本的文档不出现。
3. **Given** 当前筛选为 v1.1，**When** 改选「全部」，**Then** 表格恢复显示所有版本的文档。
4. **Given** 当前筛选为 v1.1，**Then** 表头、列定义与「版本」列的展示与筛选前完全一致，仅行集合变化。

---

### User Story 2 - 选项来自真实数据，不出现空版本 (Priority: P2)

设计者不希望下拉里出现当前根本没有文档的版本号，也不希望历史文档（版本号为空）被悄悄藏起来。

**Why this priority**: 选项与实际数据不符会直接误导判断；历史数据被隐藏则属于数据不可见，比多一个选项更糟。

**Independent Test**: 只有 v1.0 数据时，下拉为「全部 / v1.0」两项；存在版本号为空的历史文档时，下拉多一项「未填写版本」，选中后能查到这些文档。

**Acceptance Scenarios**:

1. **Given** 当前上下文只存在 v1.0 的文档，**When** 展开下拉，**Then** 只有「全部」和「v1.0」两项。
2. **Given** 存在版本号为空的历史文档，**When** 展开下拉，**Then** 出现「未填写版本」项，选中后这些文档可见。
3. **Given** 版本号形如 v1.9、v1.10、v2.0，**When** 展开下拉，**Then** 按版本新旧降序排列（v2.0 → v1.10 → v1.9），而非按字符串排序得到 v1.9 在 v1.10 之前。
4. **Given** 当前上下文没有任何需求文档，**When** 进入页面，**Then** 下拉仅有「全部」且不可展开，表格显示原有空态文案。

---

### User Story 3 - 筛选与增删操作不打架 (Priority: P2)

设计者在筛选状态下查看或删除文档，删完后页面不能停在"空版本"上让人以为数据丢了。

**Why this priority**: 删除是页面唯一写操作，与筛选叠加时最容易产生"数据消失"的误解。

**Independent Test**: 筛选到只有 1 条文档的版本，删除该文档后，下拉自动回到「全部」并提示，列表显示其余版本的文档。

**Acceptance Scenarios**:

1. **Given** 筛选 v1.0 且该版本只有 1 条文档，**When** 删除它，**Then** 下拉自动回到「全部」，列表显示剩余文档，「v1.0」选项消失。
2. **Given** 筛选 v1.0，**When** 点击「查看」进入详情再返回，**Then** 筛选状态保持为 v1.0。
3. **Given** 筛选某个版本后表格为空（例如其他端并发删除了该版本文档），**Then** 显示"该版本下暂无需求文档"的空态，且筛选控件仍可操作。

---

### Edge Cases

- **只有单一版本**：下拉仍出现（「全部」+ 该版本），不因"没得选"而隐藏控件。
- **版本号含空格或大小写差异**（如 `v1.0`、`V1.0`）：按用户输入原样展示；去重时以去除首尾空格后的原字符串比较，不做大小写合并（避免把不同版本误合并）。
- **版本号形如 `2026-11-20` 或 `v1.0-beta`**：按原样作为选项文本，排序只对"数字段"做自然比较，非数字部分按字符串比较。
- **筛选状态下删除当前版本最后一条**：自动回落到「全部」（见 US3）。
- **切换场景/本体**：筛选状态重置为「全部」，避免带入上一个上下文的版本号。
- **刷新页面**：回到「全部」（本需求不持久化筛选状态）。
- **文档数量较多**：筛选只影响展示，不改变排序、分页与「本体生成」状态的判定。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 需求汇总页面 MUST 在标题区域右侧提供一个版本号下拉筛选控件，默认选中「全部」。
- **FR-002**: 下拉选项 MUST 为「全部」+ 当前上下文（场景/本体）下所有需求文档出现过的版本号去重集合；MUST NOT 出现当前没有任何文档的版本号。
- **FR-003**: 选择具体版本号后，表格 MUST 只展示该版本的需求文档；选择「全部」MUST 恢复展示全部文档。
- **FR-004**: 版本号缺失的需求文档 MUST 归入「未填写版本」选项，选中后可见；MUST NOT 被任何筛选条件隐藏。
- **FR-005**: 版本号选项 MUST 按版本新旧降序排列（数字段按数值比较，例如 v1.10 排在 v1.9 之前）；「未填写版本」MUST 排在最后。
- **FR-006**: 筛选 MUST 在当前场景/本体上下文内生效；MUST NOT 因筛选而跨出当前上下文取数。
- **FR-007**: 切换筛选 MUST 只改变表格行集合，MUST NOT 改变列定义、行顺序规则、「本体生成」状态判定与既有操作入口。
- **FR-008**: 筛选结果为空时 MUST 显示明确的空态文案（区分"没有需求文档"与"该版本下暂无需求文档"）。
- **FR-009**: 在筛选状态下删除文档后，MUST 同步刷新列表与下拉选项；若当前选中版本已无文档，MUST 自动回落到「全部」并给出提示。
- **FR-010**: 从需求详情返回列表时，MUST 保持进入前的筛选选择。
- **FR-011**: 切换场景/本体或刷新页面时，筛选 MUST 重置为「全部」；本需求不要求跨会话记忆。
- **FR-012**: 未做任何筛选时，页面展示内容与改动前 MUST 完全一致（零回归）。

### Key Entities *(include if data involved)*

- **需求文档条目（Requirement Item）**：需求汇总表格的一行，来自某个对话导出的需求文档；与本需求相关的属性为「版本号」（可能为空）、所属场景、所属本体。
- **版本筛选选项（Version Option）**：下拉中的一项，取值为「全部」、某个实际存在的版本号，或「未填写版本」；由需求文档条目集合实时推导，不单独存储。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 选中某个版本号后，表格中不属于该版本的行数为 0。
- **SC-002**: 下拉选项与当前数据实际出现的版本号核对，缺失 0 个、多余 0 个（不含固定的「全部」）。
- **SC-003**: 切换筛选后列表更新在 200 毫秒内完成，且不因切换筛选产生额外的数据加载等待。**测量口径**：纯函数过滤在 500 条数据上的单次执行耗时 < 20 毫秒（自动化断言，不受 jsdom 渲染抖动影响）；200 毫秒为端到端人工观测值（点击到表格完成重绘），记入验收记录。
- **SC-004**: 删除当前筛选版本的最后一条文档后，100% 自动回落到「全部」，不出现"停在空版本且无提示"的状态（0 次）。
- **SC-005**: 默认进入页面（「全部」）时的行数与改动前一致，差异 0 行。
- **SC-006**: 存在版本号为空的历史文档时，通过「未填写版本」可查到的条目数与实际数量一致，遗漏 0 条。

## Assumptions

- **数据来源**：版本号取自需求文档所属对话的版本字段（新建对话时必填，历史数据可能为空），页面已有该字段，本需求不新增后端接口。
- **筛选项推导方式**：由当前已加载的需求文档列表实时去重推导，不引入"版本注册表"这类新的权威来源，避免出现"有版本却无文档"的选项。
- **过滤位置**：数据量级为百条，采用进入页面即加载、前端过滤的方式；不改为服务端分页筛选。
- **不持久化**：筛选状态不写入 URL、不写入本地存储，重新进入即回到「全部」。
- **影响范围**：仅「需求汇总」列表页；对话页、需求详情页、本体部署页均不受影响。
- **与上下文归档（009）无关**：本需求不触碰对话消息与摘要逻辑。
