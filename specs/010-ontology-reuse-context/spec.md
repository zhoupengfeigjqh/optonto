# 功能规范：新建对话时引用存量本体（命名唯一与属性对齐约束）

**Feature Branch**: `010-ontology-reuse-context`（仓库未启用 `before_specify` hook，未自动创建分支）

**Created**: 2026-11-20

**Status**: Draft

**Input**: User description:

> 1 新建对话时，除了输入版本外，还可选择存量本体（可不选、可1个或多个）（根据场景-本体名，只提取概念名-函数名-行为名-概念属性（包括 英文+中文名，属性还需完整的约束信息））。
> 2 选择后，开启对话时，作为系统提示词 append 到对话中。
> 提示词构造要求：
> 1）在本次本体构建中，确保概念、函数和行为不要出现同名异义，非常关键；
> 2）若有概念相同部分，则需保持概念-属性完全一致（如两个本体都有订单，那订单概念-属性必须完全一致）
> 3）若概念不同但有相同语义的属性，则最好保持属性信息一致。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新建对话时选择要复用的存量本体 (Priority: P1)

本体设计者在同一场景/跨场景下已经积累了一批本体。新建需求对话时，除了填版本号，他希望能勾选若干个**已存在的本体**作为参考基线；也可以一个都不选（与现在完全一样）。

**Why this priority**: 没有这一步，后面所有"命名不撞车、属性对齐"的约束都无从谈起；它也是唯一必须由用户显式参与的决策点。

**Independent Test**: 新建对话弹窗中除版本号外出现"引用存量本体"多选；不选、选 1 个、选 3 个都能创建成功；创建后对话列表与对话页能看到本次引用的本体清单。

**Acceptance Scenarios**:

1. **Given** 场景 A 下有本体 X、Y，场景 B 下有本体 Z，**When** 打开新建对话弹窗，**Then** 三个本体都以「场景名 - 本体名」的形式出现在可选项中。
2. **Given** 用户只填版本号、不选任何本体，**When** 确认创建，**Then** 对话创建成功，且后续行为与改动前完全一致。
3. **Given** 用户勾选了 X 与 Z，**When** 确认创建，**Then** 对话记录中保存两条引用，对话页显示「引用本体：A - X、B - Z」及快照时间。
4. **Given** 当前对话所属本体是 X，**When** 打开选择器，**Then** X 不出现在可选项中（避免自我引用）。
5. **Given** 某个本体没有任何概念、函数、行为，**When** 打开选择器，**Then** 该本体置灰并标注"暂无可提取内容"，不可选。

---

### User Story 2 - 对话时模型遵守命名唯一与属性对齐 (Priority: P1)

设计者引用存量本体后，希望后续对话里产出的概念、函数、行为**不再与已有命名撞车、不产生同名异义**；如果新设计与某个已有概念是同一个概念，属性必须与已有定义完全一致；如果只是语义相近的属性，也尽量保持一致。

**Why this priority**: 这是本需求的核心价值。本体最终要合并部署，命名冲突与属性不一致会在下游（数据引擎、规则、MCP 发布）变成难修的脏数据。

**Independent Test**: 引用两个含同名概念「订单」但属性不同的本体，开启对话后要求模型设计「订单」相关行为；模型输出中若沿用「订单」概念，其属性集合、类型、约束必须与引用中给出的口径一致，否则必须显式指出冲突并请用户裁决。

**Acceptance Scenarios**:

1. **Given** 引用了含概念「订单」「订单行」、函数 `sumQty`、行为「创建订单」的本体X，**When** 对话中要求设计新行为，**Then** 系统提示词中能看到这些名称，且模型不会另起同义不同名的概念（如同时出现「订单」与「销售单」表示同一事物）。
2. **Given** 本体 X 的「订单」属性为 `orderNo(string, 必填/唯一)`、`amount(number, ≥0)`，本体 Y 的「订单」属性为 `orderNo(string)`、`total(number)`，**When** 开始对话，**Then** 系统在创建对话时已明确提示这两处冲突，并在提示词中把两组定义都列出、要求模型不得自行取舍。
3. **Given** 两个本体都没有「客户」，但 X 有 `customerCode(string)`、Y 有 `custNo(string)`，**When** 模型设计「客户」概念，**Then** 提示词要求优先沿用已有的属性命名与类型，而不是再造第三个写法。
4. **Given** 引用列表为空，**When** 开始对话，**Then** 系统提示词与改动前完全一致（不追加任何段落）。

---

### User Story 3 - 已存在的命名冲突在创建前就暴露 (Priority: P2)

设计者在勾选多个存量本体时，可能并不知道它们之间本来就有同名异义。系统应在创建对话之前把冲突列出来，让他决定是否继续。

**Why this priority**: 冲突提示不阻断主流程，但直接影响引用质量；没有它，User Story 2 的"完全一致"要求在一开始就不可满足。

**Independent Test**: 勾选两个含同名但定义不同的概念的本体，创建前出现冲突清单（同名概念 + 两边的属性差异），确认后仍可创建；未勾选冲突组合时不出现提示。

**Acceptance Scenarios**:

1. **Given** 勾选的 X、Y 存在同名概念「订单」但属性不同，**When** 点击确认创建，**Then** 先弹出冲突清单（概念名、属性名、两边的类型/约束差异），用户确认后才创建。
2. **Given** 勾选的 X、Y 存在同一个名字同时被用作概念和函数（如都叫 `Order`），**When** 确认创建，**Then** 冲突清单中标注"跨类目同名"，并说明可能导致同名异义。
3. **Given** 用户看到冲突后取消，**Then** 不创建对话，选择状态保留，可调整后重试。

---

### User Story 4 - 引用结果可追溯，不因原本体变动而漂移 (Priority: P3)

设计者过几天回来继续这段对话，需要知道当初引用了哪些本体、引用的是什么时候的内容。

**Why this priority**: 可追溯性影响信任度，但不影响首版核心价值。

**Independent Test**: 对话创建后修改被引用本体的概念属性，再次进入该对话，其引用内容与提示词仍保持创建时的口径；页面显示快照时间。

**Acceptance Scenarios**:

1. **Given** 对话引用了本体 X，**When** 在别处把 X 的「订单」属性删掉一个，**Then** 本对话的引用内容不变，页面仍显示原快照时间。
2. **Given** 被引用本体后来被删除，**When** 进入该对话，**Then** 对话照常可用，引用清单标记"原本体已不存在"。
3. **Given** 用户清空该对话的消息，**When** 再次进入，**Then** 引用清单仍然存在（引用是会话级配置，不是消息派生物）。

---

### Edge Cases

- **重复选择**：同一本体被重复勾选时按一条处理（去重）。
- **提取内容超限**：所选本体合计提取内容超过注入上限（初始按 20,000 tokens 计）时，创建被阻止并给出可操作提示（"减少勾选或换更小的本体"），**不得静默截断**。
- **中文名缺失**：概念/属性/函数/行为没有中文名时只输出英文名，禁止用英文名冒充中文名或自行编造。
- **属性约束为空**：属性没有任何约束时，不输出空的约束段落（避免模型误读为"无约束要求"）。
- **同场景多本体但无交集**：正常创建，提示词只做命名清单，不做额外说明。
- **选择器无任何可选项**：显示空态说明（"当前没有可引用的存量本体"），仍可填写版本号创建。
- **清空对话与上下文归档的关系**：清空消息会清除上下文摘要，但**不得**清除引用本体配置。
- **本体名/概念名含特殊字符**：按原样输出，不做转义或改写。

## Requirements *(mandatory)*

### Functional Requirements

**选择与创建**

- **FR-001**: 新建对话弹窗 MUST 在版本号之外提供"引用存量本体"多选控件，允许 0 个、1 个或任意多个（不含重复计数）。
- **FR-002**: 可选项 MUST 覆盖所有场景下的存量本体，每项以「场景名 - 本体名」标识；当前对话所属本体自身 MUST NOT 出现在可选项中。
- **FR-003**: 没有任何概念、函数、行为的本体 MUST 置灰不可选，并标注原因。
- **FR-004**: 未选择任何本体时，创建流程与对话行为 MUST 与改动前完全一致。
- **FR-005**: 勾选结果 MUST 随对话一起持久化，并在对话页可见（清单 + 快照时间）。

**内容提取（严格限界）**

- **FR-006**: 系统 MUST 只提取以下四类信息，MUST NOT 提取概念关系、对象关系、规则、流程、安全管控、数据引擎：
  - 概念：英文名 + 中文名
  - 概念属性：英文名 + 中文名 + 类型 + 完整约束（是否唯一、是否必填、枚举值、匹配模式、最小值、最大值）
  - 函数：英文名 + 中文名
  - 行为：英文名 + 中文名
- **FR-007**: 中文名缺失时 MUST 留空或省略该字段，MUST NOT 用英文名填充中文名位。
- **FR-008**: 属性无任何约束时，MUST NOT 输出空约束描述。

**提示词构造**

- **FR-009**: 选定本体后，系统 MUST 在各轮对话的系统提示词中追加一个独立段落（"存量本体参考"），与既有系统提示词主体、拷问模式段、业务基线段、历史摘要段共存且互不覆盖；未选定本体时 MUST NOT 追加。
- **FR-010**: 该段落 MUST 明确要求：本次构建中概念、函数、行为三类不得出现同名异义；同类目内名称唯一；跨类目同名必须显式说明。
- **FR-011**: 该段落 MUST 明确要求：与存量本体中**同名概念**，其属性集合、属性类型、属性约束 MUST 与存量定义完全一致。
- **FR-012**: 该段落 MUST 明确要求：概念不同但语义相同的属性，SHOULD 沿用存量中的属性英文名、类型与约束。
- **FR-013**: 该段落 MUST 说明这些名称是**既有约定**，不得被重新命名或合并；如与用户新输入冲突，MUST 先向用户确认而不是自行取舍。
- **FR-014**: 当被选本体之间存在同名概念且属性不一致、或同名跨类目时，系统 MUST 在创建对话前列出冲突清单（名称 + 双方差异），并要求用户确认后才能创建。
- **FR-015**: 提取内容合计超过注入上限时，系统 MUST 阻止创建并提示减少选择；MUST NOT 截断后静默继续。

**一致性与可追溯**

- **FR-016**: 引用 MUST 是创建时的快照；被引用本体后续被修改或删除，MUST NOT 改变该对话的引用内容与提示词。
- **FR-017**: 清空对话消息 MUST NOT 清除引用本体配置。
- **FR-018**: 删除对话时，引用配置随对话一并删除。

### Key Entities *(include if data involved)*

- **对话引用快照（Conversation Ontology Reference）**：某段需求对话引用的存量本体集合。属性包括：被引用本体标识（场景名 + 本体名）、快照内容（四类提取项）、快照时间、内容体量。
- **提取项（Extracted Item）**：一条可被引用的命名实体，类目为概念 / 概念属性 / 函数 / 行为；属性包括英文名、中文名、所属概念（仅属性）、类型（仅属性）、约束（仅属性）。
- **冲突项（Conflict）**：两个及以上被引用本体在同一名称上的定义分歧。属性包括冲突名称、冲突类型（同名概念属性不一致 / 跨类目同名）、参与方及各自的定义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 勾选 3 个存量本体创建对话，从点击确认到进入对话界面 ≤ 3 秒（不含用户思考时间）。
- **SC-002**: 随机抽样 5 段引用对话，其系统提示词中的概念名、属性（含中文名与约束）、函数名、行为名与源本体清单核对，缺失 0 项、多出 0 项（即不混入关系/规则等未声明的类目）。
- **SC-003**: 用 3 组含"跨本体同名概念"的样例进行 10 轮对话，产出的概念/函数/行为中同名异义 0 处。
- **SC-004**: 同名概念的属性对齐检查：属性英文名、类型、约束（唯一/必填/枚举/正则/上下界）与存量定义不一致 0 处。
- **SC-005**: 不勾选任何本体时，系统提示词与改动前逐字节一致（零回归）。
- **SC-006**: 提取内容超过上限时，100% 在创建前被拦截并给出可操作提示，0 次静默截断。
- **SC-007**: 被引用本体在对话创建后被修改，重新进入该对话时引用内容变化 0 处。

## Assumptions

- **跨场景可选**：按用户表述「根据场景-本体名」，被引用本体以「场景名 + 本体名」标识，允许跨场景勾选。若后续要求限定为"仅当前场景"，属于可逆的范围收窄，不影响本条之外的设计。
- **快照语义**：创建时拍快照（而非每轮实时读取），以保证多轮对话中参考基线稳定、可复现；代价是原本体变更不会自动同步。
- **创建后不可修改引用**：首版引用集合在创建时确定，需要变更时新建对话。若后续反馈强烈，可扩展为对话页内修改并重建快照。
- **注入上限**：初始按 20,000 tokens 计（与系统现有单条消息上限同量级），实际数值在方案阶段确定并回写本节。
- **提取范围严格四类**：用户明确只提取概念名、属性、函数名、行为名；关系/规则/流程等信息即使对建模有价值也**不纳入**本需求，避免提示词体量失控。
- **冲突提示不阻断**：存量本体之间的冲突是既成事实，系统只负责暴露并要求确认，不代用户裁决，也不自动改名。
- **依赖既有能力**：系统已具备按场景列出本体、读取本体明细（概念/函数/行为/属性及其约束）的能力，本需求不新增本体编辑能力。
- **术语**：本文档中"存量本体"指对话创建之前已存在于平台、且已保存过内容的本体；"引用"指把其四类命名信息作为对话背景，不产生任何写回。
